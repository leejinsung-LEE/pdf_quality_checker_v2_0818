# 대형 프로젝트 개발용 체계적 프롬프트 템플릿

## 목적
대형 프로젝트에서 기술 부채를 최소화하고 예상치 못한 문제를 방지하기 위한 체계적인 프롬프트 모음

## 1. 아키텍처 영향도 분석 프롬프트
```
이 변경사항을 구현하기 전에:
1. 영향 받는 모든 모듈 나열
2. 기존 인터페이스와의 호환성 검증
3. 순환 의존성 체크
4. 성능 병목 지점 예측
5. 롤백 계획 수립
```

## 2. 기술 부채 방지 프롬프트
```
코드 작성 전 체크리스트:
- [ ] 기존 유사 기능 있는지 검색 (중복 방지)
- [ ] 현재 코딩 컨벤션 확인
- [ ] 테스트 가능한 설계인지 검증
- [ ] 문서화가 필요한 복잡도인지 판단
- [ ] 6개월 후 다른 개발자가 이해할 수 있는가?
```

## 3. 의존성 관리 프롬프트
```
새 라이브러리/모듈 추가 시:
- 정말 필요한가? (기존 도구로 해결 가능?)
- 라이선스 충돌은 없는가?
- 보안 취약점은 없는가?
- 유지보수가 활발한가?
- 대안은 무엇인가?
```

## 4. 리팩토링 안전성 프롬프트
```
리팩토링 전 필수 확인:
1. 현재 코드의 모든 사용처 파악
2. 테스트 커버리지 확인
3. 단계별 마이그레이션 계획
4. 구버전 호환성 필요 여부
5. 예상 사이드 이펙트 목록화
```

## 5. 코드 리뷰 시뮬레이션 프롬프트
```
내가 작성한 코드를 까다로운 시니어 개발자 관점에서 리뷰해줘:
- 엣지 케이스 처리
- 에러 핸들링 누락
- 메모리 누수 가능성
- 동시성 문제
- SOLID 원칙 위반
```

## 6. 성능 최적화 프롬프트
```
이 기능의 성능 분석:
- Big O 복잡도는?
- 메모리 사용량 예측
- DB 쿼리 횟수
- 캐싱 가능 지점
- 병렬처리 가능 여부
```

## 7. 에러 처리 완성도 프롬프트
```
모든 실패 시나리오 검토:
- 네트워크 장애
- 파일 시스템 권한
- 메모리 부족
- 잘못된 입력값
- 외부 서비스 장애
각각에 대한 graceful degradation 전략은?
```

## 8. 확장성 검증 프롬프트
```
향후 요구사항 대비:
- 데이터가 100배 늘어나면?
- 동시 사용자가 1000명이면?
- 새로운 기능 추가 시 수정 범위는?
- 국제화가 필요하다면?
- 플랫폼을 확장한다면?
```

## 9. 통합 테스트 설계 프롬프트
```
이 기능의 완전한 테스트를 위해:
1. Happy path 시나리오
2. 모든 예외 상황
3. 경계값 테스트
4. 상태 전이 테스트
5. 동시성 테스트
6. 롤백 테스트
```

## 10. 기술 부채 탐지 프롬프트
```
현재 코드베이스 분석:
- TODO/FIXME 주석 위치와 우선순위
- 중복 코드 패턴
- 과도하게 복잡한 함수 (cyclomatic complexity)
- 오래된 의존성
- 사용하지 않는 코드
- 일관성 없는 네이밍
```

## 11. 데이터 무결성 프롬프트
```
데이터 처리 로직 검증:
- 트랜잭션 경계 설정
- 동시성 제어 (락, 세마포어)
- 데이터 유효성 검증 시점
- 부분 실패 시 복구 전략
- 감사(audit) 로그 필요성
```

## 12. 보안 체크 프롬프트
```
보안 취약점 스캔:
- SQL Injection 가능성
- XSS 취약점
- 인증/인가 우회 가능성
- 민감 정보 노출
- 암호화 필요 데이터
- Rate limiting 필요성
```

## 13. 모니터링 준비도 프롬프트
```
운영 환경 대비:
- 로깅 레벨과 내용 적절성
- 메트릭 수집 포인트
- 알람 조건 정의
- 디버깅을 위한 정보 충분성
- 성능 프로파일링 가능 여부
```

## 14. 문서화 완성도 프롬프트
```
문서화 체크리스트:
- API 명세 완성도
- 설치/배포 가이드
- 트러블슈팅 가이드
- 아키텍처 다이어그램
- 주요 의사결정 기록 (ADR)
```

## 15. 배포 안전성 프롬프트
```
배포 전 최종 점검:
- 설정 파일 환경별 분리
- 기능 플래그 준비
- 롤백 시나리오
- 데이터 마이그레이션 계획
- 다운타임 최소화 전략
- 카나리 배포 가능 여부
```

## 사용 방법

### 일반 사용
각 프롬프트를 상황에 맞게 AI 도구(Claude, GPT 등)에 입력하여 코드 리뷰, 설계 검증, 문제 예측에 활용

### 체크리스트로 활용
프로젝트 단계별로 해당 프롬프트를 체크리스트로 사용하여 누락 사항 점검

### 팀 표준으로 도입
팀 내 코드 리뷰 가이드라인이나 PR 템플릿에 포함시켜 일관된 품질 관리

## 프로젝트별 커스터마이징

이 프롬프트들을 프로젝트 특성에 맞게 수정하여 사용:
- 도메인 특화 검증 항목 추가
- 기술 스택별 세부 체크 포인트 구체화
- 팀 컨벤션 반영

## 지속적 개선

프로젝트 진행 중 발견된 문제들을 바탕으로 프롬프트를 계속 업데이트하여 더 강력한 방어막 구축
